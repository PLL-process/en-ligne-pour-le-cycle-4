C4.7 · 10 notions

Adresse valable
Adresse valable = bonne rue + numéro unique + .1 respecté.
Concevoir le plan
Plan d'adressage : recenser → choisir la rue → numéros uniques (.1 réservé) → masque.
La fenêtre d'adressage
Adresse fixe : Desktop → IP Configuration → Static + IPv4 + masque + passerelle.
Fixe ou automatique
Objet connecté à joindre = adresse FIXE (Static). Appareil de passage = DHCP.
La ligne Default Gateway
Default Gateway = adresse de la passerelle (192.168.20.1), pas la sienne.
Lire une adresse
Adresse = rue (3 premiers nombres, commune) + maison (dernier nombre, unique).
La passerelle
Le .1 est réservé à la passerelle — la porte du réseau. Convention quasi universelle.
Le plan de référence
Dans un réseau local simple : UN masque, le même pour tous (255.255.255.0).
Preuve du paramétrage
Paramétrage réussi = prouvé par un ping (« Reply from … », 0% loss).
Le rôle du masque
255.255.255.0 : les 255 marquent la rue, le 0 marque le numéro de maison.

C4.8 · 10 notions

La boucle du dépanneur
Toujours : symptôme → hypothèse → test → remède → RE-test.
Choisir le bon test
Premier test = le moins invasif qui peut trancher l'hypothèse (souvent : LIRE la configuration).
Doublon vs mauvaise rue
Doublon et mauvaise rue = famille ADRESSAGE : liens verts, livraison cassée.
Familles de pannes
Adressage : liens verts + timeout. Liaison : triangles rouges. Familles différentes, remèdes différents.
Lire le symptôme
Request timed out = zéro réponse. 100% loss = communication rompue.
La panne mauvaise rue
Changer la rue d'une adresse = disparaître du réseau. Câble vert n'innocente pas l'adresse.
Le re-test
Pas de réparation sans RE-TEST réussi. C'est la signature du dépanneur.
Réseau d'entraînement
On s'entraîne sur simulation ou réseau isolé : provoquer des pannes sans danger, c'est le seul moyen d'apprendre à les réparer.
Triangles rouges
Triangles rouges = liaison tombée. Vérifier port et câble, pas l'adresse.
TTL et bonne santé
Réseau local sain : temps de 0 à ~15 ms, perte 0%. La PERTE est le vrai signal d'alerte.

C4.9 · 10 notions

Compléter, pas reconstruire
Compléter une simulation = ajouter le test (PDU) au fichier fourni, pas refaire le montage.
Du simulateur au réel
Simulation validée = logique juste. Le réel exigera son propre re-test.
Lire l'Event List
Event List = le trajet écrit et horodaté du message. La preuve noire sur blanc.
L'outil enveloppe
Add Simple PDU : 1er clic expéditeur, 2e clic destinataire — le test entre au scénario.
Realtime vs Simulation
Simulation = le temps au ralenti, message par message. L'outil d'observation du réseau.
Sauvegarder le scénario
Sauvegarder après le test : le scénario devient rejouable — le fichier raconte ta validation.
Simulation et panne
En panne, la simulation montre le dernier arrêt du message : la panne est juste après.
Trajet dans l'étoile
Étoile = tout passe par le commutateur. La simulation en donne la preuve visuelle.
Valider un comportement
Valider = test + verdict conforme à l'attendu. Jamais « à l'œil ».
Le verdict
Successful = aller-retour simulé réussi = comportement du réseau VALIDÉ.
