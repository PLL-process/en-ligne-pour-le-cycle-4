📌 Synthèse élève — SOS serre (4e_C4.7 · C4.8 · C4.9)

Comment ajouter un objet connecté à un réseau local — et retrouver, avec méthode, la panne qui l'empêche de communiquer ?

1. Le plan d'adressage (4e_C4.7)

La recette (AVANT de brancher)
① recenser les habitants → ② choisir la rue commune (192.168.20) → ③ un numéro unique par appareil, le .1 réservé → ④ écrire le masque.
Passerelle (gateway)
la porte de sortie du réseau vers les autres réseaux — son adresse (192.168.20.1) est réservée et notée dans le carnet de chaque habitant. Dans notre serre, la porte est prévue au plan mais pas encore installée : c'est pour cela que les pings entre voisins marchent quand même.
Masque
255.255.255.0 = « les 3 premiers nombres sont la rue, le dernier est la maison » — dans notre réseau, qui utilise ce masque-là. D'autres masques existent ; tu les verras plus tard. Le même pour toute la rue.
Le « .1 »
ce n'est pas une loi de l'informatique : c'est une convention très répandue (et la nôtre). On réserve le .1 à la passerelle pour que tout le monde sache où est la porte.

2. L'adresse IP fixe (4e_C4.7)

Pourquoi FIXE ?
un objet connecté qu'on doit joindre à coup sûr (capteur, serveur, imprimante) ne peut pas changer d'adresse au hasard → Static, pas DHCP.
Les 4 lignes
Static coché · IPv4 192.168.20.50 · masque 255.255.255.0 · Default Gateway 192.168.20.1 ⭐ la nouveauté de 4e.
La preuve qui compte
le ping vers l'objet que tu viens d'adresser : ping 192.168.20.50 → Reply from… ×4, 0% loss, TTL=128. C'est CE ping qui prouve que TON paramétrage marche — pas un ping au hasard.
Le premier ping
il arrive souvent qu'il affiche Request timed out tout seul, puis que les suivants répondent : le réseau « se réveille ». Ne panique pas, relance une fois avant de conclure à une panne.

3. Valider par la simulation (4e_C4.9)

Compléter, pas reconstruire
le fichier .pkt est fourni : on y ajoute le test (Add Simple PDU : clic expéditeur → clic destinataire), puis Play.
Lire le film
l'Event List horodate chaque étape : 0.000 PC-Prof → 0.001 Switch0 → 0.002 Serveur. Tout passe par le commutateur (étoile).
Le verdict
Successful = aller-retour simulé réussi = comportement du réseau validé. On sauvegarde : le test fait partie du fichier.

4. Dépanner avec méthode (4e_C4.8)

La boucle du dépanneur
symptôme → hypothèse → test → remède → RE-test. Jamais de remède sans test, jamais de « réparé » sans re-test.
Famille « adressage »
liens verts mais Request timed out (100% loss) → vérifier les adresses. Ex. réel : la mauvaise rue 192.168.21.50 — une unité d'écart, et le capteur « déménage » hors du réseau.
Famille « liaison »
triangles ROUGES → la route est coupée (port sur Off, câble défait). Ex. réel : le Port Status de l'imprimante décoché. Remède : On → vert → re-ping.
Famille « masque »
tout a l'air juste, l'adresse est dans la bonne rue… mais le masque est faux (ex. réel : 255.255.255.240 sur le capteur). Résultat : 100% loss. Le masque décide de qui est « dans la rue » : se tromper de masque, c'est déménager sans changer d'adresse.

5. Ma fiche d'intervention (le geste du pro)

Trois fichiers en panne
4e_serre_PANNE_A.pkt · 4e_serre_PANNE_B.pkt · 4e_serre_PANNE_C.pkt : de vraies pannes, préparées puis vérifiées dans Packet Tracer. À toi de les diagnostiquer.
Les 6 lignes à écrire
① le symptôme observé · ② mon hypothèse · ③ le test que je lance · ④ ce que le test montre · ⑤ le remède appliqué · ⑥ le re-test qui prouve la réparation.
La règle d'or
on n'écrit jamais « réparé » sans avoir collé la preuve du re-test. Un dépanneur qui ne re-teste pas n'a rien prouvé.
Le fichier de départ
4e_serre_DEPART.pkt : le montage est déjà câblé, les adresses sont vides. La compétence évaluée n'est pas de retrouver le commutateur dans la palette : c'est d'adresser et de prouver.

✅ Je dois savoir

  • concevoir un plan : rue commune, numéros uniques, .1 réservé, masque commun ;
  • expliquer fixe vs DHCP (joindre ≠ passer) ;
  • lire un ping : Reply / timed out / % loss ;
  • distinguer les trois familles de pannes : adressage, liaison, masque ;
  • dire ce que valide un « Successful » de simulation.

🛠 Je dois savoir faire

  • paramétrer Static + IPv4 + masque + passerelle dans IP Configuration ;
  • prouver un paramétrage au ping ;
  • dérouler la boucle du dépanneur sur une panne ;
  • ajouter un PDU au fichier fourni et lire l'Event List ;
  • rédiger une fiche d'intervention en 6 lignes sur un fichier en panne ;
  • choisir seul·e le test qui prouve une communication, sans procédure sous les yeux.

⚠ Pièges classiques

  • donner le .1 à un appareil (la porte est réservée) ;
  • changer de rue sans s'en rendre compte (21 ≠ 20) ;
  • accuser le câble quand les triangles sont verts — ou l'adresse quand ils sont rouges ;
  • réparer sans re-tester ;
  • oublier le masque quand l'adresse a l'air juste (255.255.255.240 ≠ 255.255.255.0) ;
  • conclure « panne » dès le premier ping raté ;
  • reconstruire le fichier fourni au lieu de le compléter.
