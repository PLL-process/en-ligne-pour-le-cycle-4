📌 Synthèse élève — Le réseau de la salle techno (5e_C4.7 · 5e_C4.8)

Comment organiser et identifier les appareils pour que chaque message arrive, à coup sûr, au bon destinataire ?

1. Les composants du réseau local (5e_C4.7)

Terminal
un appareil qui envoie ou reçoit des messages : PC, imprimante, portable, tablette, smartphone… (les « destinataires » du jeu du facteur).
Commutateur
le boîtier central où arrivent tous les câbles : il lit l'adresse de destination et redistribue chaque message vers le bon terminal (le « facteur »).
Liaisons
filaire = un câble (trait plein) · sans fil (WiFi) = des ondes (pointillés), grâce au point d'accès qui fait le pont entre les ondes et le câble. Son nom de réseau s'appelle le SSID (ex. TECHNO-C4).
Topologie
la forme du réseau. Tout passe par le centre → topologie en étoile : si une branche casse, les autres continuent.

2. Identifier chaque terminal : l'adresse IP (5e_C4.8)

Chaque terminal porte une adresse IP qui se lit comme une adresse postale : 192.168.10.30 = la « rue » commune à toute la salle + le « numéro de maison », UNIQUE pour chaque appareil. Notre table : PC0 .10 · PC1 .20 · portable .30 · tablette .40 · smartphone .50. On la règle dans : Desktop → IP Configuration → Static (la case Subnet Mask se remplit toute seule : on n'y touche pas en 5e). Un doublon d'adresse casse la livraison : le réseau ne sait plus qui est qui — vérifié en simulation !

3. Les preuves que ça marche

Le ping
le test de livraison : ping 192.168.10.20 envoie 4 messages-tests. « Reply from » = réponse reçue → l'aller ET le retour fonctionnent. « Request timed out » = pas de réponse. ⚠ Le tout premier ping peut afficher un ou deux « timed out » avant que les réponses arrivent : le réseau apprend les correspondances. Relance-le une fois avant de conclure à une panne.
L'enveloppe (Simulation)
le trajet réel du message : PC0 → Switch0 → PC1. L'enveloppe passe TOUJOURS par le commutateur, le centre de l'étoile.
Câble ou WiFi ?
valeurs réellement observées pendant notre simulation — filaire : <1 ms, rapide et régulier · WiFi : 57 à 260 ms, pratique mais plus lent et variable. Les deux livrent !

4. Construire dans Packet Tracer

  • palette → glisser commutateur 2960, PC, point d'accès, tablette, smartphone ;
  • câble Copper Straight-Through (cuivre droit) : prise FastEthernet0 du PC → prise LIBRE du commutateur (FastEthernet0/1 … 0/24) ;
  • triangles : 🟠 démarre · 🟢 ça marche · 🔴 problème ;
  • WiFi : SSID TECHNO-C4 sur le point d'accès, module WPC300N sur le portable (éteindre → changer → rallumer) ;
  • enregistrer : reseau_5X_NOM_Prenom.pkt.

✅ Je dois savoir

  • nommer les composants : terminal, commutateur, liaison filaire, liaison sans fil (WiFi), point d'accès ;
  • reconnaître la topologie en étoile et son avantage ;
  • lire une adresse IP : la « rue » commune + le numéro unique ;
  • justifier pourquoi chaque terminal doit être identifié de façon unique ;
  • interpréter « Reply from » et « Request timed out ».

🛠 Je dois savoir faire

  • identifier les composants sur un schéma de réseau (ou l'écran du simulateur) ;
  • construire le réseau de la salle dans Packet Tracer, câbles et WiFi compris ;
  • donner une adresse IP valide (même rue, numéro libre) à un terminal ;
  • prouver une livraison avec un ping et suivre l'enveloppe en mode Simulation ;
  • provoquer, reconnaître et réparer la panne du doublon d'adresse.

⚠ Erreurs à éviter

  • compter le commutateur ou le point d'accès parmi les terminaux ;
  • croire que le WiFi se connecte « tout seul » : il faut TOUJOURS un point d'accès ;
  • changer les 3 premiers nombres d'une adresse (l'appareil « déménage » de rue et ne reçoit plus rien) ;
  • réutiliser l'adresse d'un appareil éteint : il la garde, et le doublon explosera à son réveil ;
  • confondre « Reply from » (réponse reçue) et « Request timed out » (pas de réponse).
