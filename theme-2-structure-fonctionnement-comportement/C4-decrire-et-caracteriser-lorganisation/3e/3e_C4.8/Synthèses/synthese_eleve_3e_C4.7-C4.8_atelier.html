📌 Synthèse élève — Le pont numérique Martinique → New York (3e_C4.7 · C4.8)

Comment un message franchit-il la frontière entre deux réseaux — et pourquoi Internet a-t-il besoin d'un protocole de routage ?

1. Deux réseaux, un pont (3e_C4.7)

La recette (AVANT le logiciel)
① deux quartiers, deux rues différentes (192.168.10 / 192.168.30) → ② un routeur à la porte de chaque quartier → ③ la rue-pont 10.0.0.0/30 entre les deux (câble croisé) → ④ chaque quartier garde son commutateur.
Le routeur = le poste-frontière
il a deux adresses : le .1 de sa rue (la passerelle de 4e — elle a maintenant un corps !) + son pied sur la rue-pont (10.0.0.1 ou 10.0.0.2).
Le trajet complet
PC-MQ → Switch-MQ → R-MQ → (pont) → R-NY → Switch-NY → Serveur-NY — et le retour en miroir.

2. La table de routage (3e_C4.8)

À chaque frontière
le routeur applique SA table : rue dans la table → transmettre au « via » ; rue directement connectée → distribuer ; rue inconnue → détruire (jamais au hasard).
Notre route statique réelle
192.168.30.0/24 via 10.0.0.2 — écrite À LA MAIN dans R-MQ (et son miroir dans R-NY : sans retour, pas de réponse !).
Pourquoi un protocole ?
2 réseaux = 2 lignes à écrire… mais Internet = des dizaines de milliers de réseaux : impossible à la main. Le protocole de routage (les routeurs s'informent mutuellement) est nécessaire.

3. Les preuves du voyage (3e_C4.7)

ping
prouve l'aller-retour : Reply… TTL=126 (les 2 premiers échecs sont normaux : relancer !). Second ping réel : 0% loss, 0-4 ms.
TTL
compte les frontières : 128 − 2 routeurs = 126. Un seul chiffre, et tu SAIS combien de postes-frontières le message a traversés.
tracert
liste les sauts un par un : 192.168.10.1 → 10.0.0.2 → 192.168.30.10, « Trace complete ». C'est le chemin que la table a décidé.
Simulation
le film horodaté : 0.000 → 0.010 s, 11 étapes, verdict Successful — et SANS la route, l'enveloppe est détruite à R-MQ.

✅ Je dois savoir

  • représenter deux réseaux reliés par des routeurs et une rue-pont ;
  • appliquer la procédure du poste-frontière (transmettre / distribuer / détruire) ;
  • lire TTL et tracert pour retrouver le chemin d'un message ;
  • justifier la nécessité d'un protocole de routage (l'argument du nombre) ;
  • citer ma preuve expérimentale : route effacée = plus rien ne passe.

🛠 Je dois savoir faire

  • concevoir le schéma à deux réseaux AVANT d'ouvrir le logiciel ;
  • configurer les deux prises d'un routeur (G0/0 quartier, G0/1 pont) ;
  • écrire une route statique (Network / Mask / Next Hop / Add) ;
  • prouver le voyage : ping, tracert, mode Simulation (Event List).

⚠ Pièges classiques

  • oublier la route MIROIR dans R-NY : l'aller connaît le chemin, pas le retour ;
  • confondre commutateur (distribue DANS le quartier) et routeur (franchit les frontières) ;
  • croire qu'un routeur « essaie quand même » : rue inconnue = paquet détruit ;
  • conclure « panne » sur les 2 premiers timeouts du ping — relancer d'abord ;
  • mettre un câble droit entre les deux routeurs (il faut un câble croisé).
