C6.1 · 15 notions

Constante
Constante nommée (MAJUSCULES) = paramètre modifiable en un seul point.
Donnée lue non utilisée
Identifier les données révèle aussi les entrées INEXPLOITÉES : des pistes d'amélioration.
Donnée produite
Donnée produite = créée par le programme (résultat, commande, message).
Donnée utilisée
Donnée utilisée = lue depuis l'extérieur (capteur, constante, saisie).
Fonctionnalité
Fonctionnalité = service rendu ; le programme n'est que sa réalisation.
Initialisation
Initialiser les sorties à un état SÛR avant les décisions : actionneurs au repos par défaut.
Lire avant modifier
Comprendre (C6.1) avant de modifier (C6.3) : toujours dans cet ordre.
Ordre des tests
Avec des elif sur des seuils, tester du plus FORT au plus FAIBLE.
Pourquoi identifier les données
Identifier entrées/sorties = savoir ce que la modification peut impacter ailleurs.
Rôle du elif
if/elif = un seul chemin : le premier test vrai gagne, les autres sont ignorés.
Sorties vers le système
Les sorties de la v1 : vigilance (résultat), sirene_active (commande), message (information).
Trace simple
Les elif se testent dans l'ordre et s'arrêtent au premier vrai.
Transfert
La carte d'identité entrées/sorties s'établit par la lecture, sur n'importe quel programme.
Valeur frontière
> est strict : à la frontière exacte, le test échoue. C'est là que > et >= diffèrent.
Variable réutilisée
Au sein du programme, une donnée produite peut être réutilisée ; le classement C6.1 se fait vis-à-vis de l'extérieur.

C6.3 · 15 notions

Diagnostiquer par le test
Un échec de test aux frontières oriente vers l'opérateur de comparaison.
L'erreur d'indentation
Lire le message d'erreur : type + ligne = la moitié de la correction.
Étendre la structure
Étendre = nouvelle constante + elif à la bonne place dans l'ordre + tests aux nouvelles frontières.
Imiter le modèle
Étendre un programme = imiter ses motifs validés (initialisation → décision → commande).
Indentation
En Python, l'indentation fait partie du langage : elle délimite les blocs.
Jeu d'essai
Jeu d'essai = entrée + sortie attendue (à la main) + sortie obtenue + verdict.
Lire l'algorigramme
On implémente une SPÉCIFICATION (algorigramme), pas une intuition.
Modifier un paramètre
Modifier un paramètre = changer SA constante, en un seul point.
Modifier vs valider
C6.3 = modifier + tester, indissociables : la preuve fait partie de la modification.
Non-régression
Après toute modification : tester le NOUVEAU et re-tester l'ANCIEN (non-régression).
Prédire l'effet
Après chaque modification : re-tracer les cas concernés.
Sauvegarder et versionner
Toujours garder la version qui marche : comparer et pouvoir revenir en arrière.
Un seul échec
Validation = TOUS les tests passent. Un échec → corriger → tout rejouer.
Tester sans machine
Tester = comparer attendu et obtenu ; la trace manuelle est un vrai test.
Valeurs frontières
Tester AUX frontières : seuil-1, seuil, seuil+1.
