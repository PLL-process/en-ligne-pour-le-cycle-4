# 4e_C8.3 — Proposer un protocole de test (couvert par une séquence mutualisée)

> Proposer un protocole de test pour valider le comportement et les performances
> d'un objet technique.

Ce code est travaillé par la séquence **« Jardin connecté — valider une solution »**,
dont le dossier principal est [`4e_C8.1`](../4e_C8.1/README.md) :

➡ **[Ouvrir la séquence](../4e_C8.1/sequence_4e_C8_jardin-validation.html)** — le code
se joue sur trois moments :

* **Activité 2 — Analyser les résultats** : le comportement de l'objet entier est mis
  à l'épreuve sur quatre critères de nature différente — stabilité, étanchéité,
  visibilité de la LED à 3 m en plein soleil, tenue d'une attache à −8 °C. Ce ne sont
  pas quatre mesures d'une même grandeur : c'est un objet jugé sur ce qu'il doit
  faire.
* **Activité 3 — Améliorations** (~15 min) : chaque amélioration doit être **rattachée
  à un résultat d'essai précis**. La consigne est nette — « une amélioration qui ne
  cite aucun résultat d'essai est une idée, pas une correction ». Et l'élève doit dire
  **quels essais rejouer** après modification, pas seulement celui qui avait échoué :
  c'est la non-régression, énoncée sans le mot.
* **Le réinvestissement** (~15 min), qui redemande la démarche sur un autre objet.
