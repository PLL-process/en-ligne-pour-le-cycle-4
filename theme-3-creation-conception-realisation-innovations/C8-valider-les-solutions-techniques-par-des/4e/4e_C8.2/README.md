# 4e_C8.2 — Proposer un protocole de test (couvert par une séquence mutualisée)

> Proposer un protocole de test pour valider la tenue mécanique d'un matériau.

Ce code est travaillé par la séquence **« Jardin connecté — valider une solution »**,
dont le dossier principal est [`4e_C8.1`](../4e_C8.1/README.md) :

➡ **[Ouvrir la séquence](../4e_C8.1/sequence_4e_C8_jardin-validation.html)** — deux
activités y portent 4e_C8.2 :

* **Activité 1 — Le protocole en diagramme de flux, puis en tableau** (~20 min) :
  l'élève remet en ordre le raisonnement de validation. L'ordre est le fond même du
  code — *écrire le résultat attendu AVANT d'essayer*, exécuter, comparer, et faire
  remonter la flèche vers un nouvel essai quand ça ne passe pas. La séquence le dit
  sans détour : « un essai dont l'attendu est rédigé après coup ne prouve rien ».
* **Activité 2 — Analyser les résultats** (~20 min) : quatre essais à juger conformes
  ou non, puis le geste qui distingue vraiment ce code du simple constat — nommer une
  cause probable **et le test qui la départagerait d'une autre**. Proposer un
  protocole, ce n'est pas dérouler une recette : c'est choisir l'essai qui tranche.

La séquence porte elle-même le tableau « Ce que dit le programme — recopié, pas
reformulé », où cette correspondance est écrite noir sur blanc.
