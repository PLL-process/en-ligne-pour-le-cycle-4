1. Où le programme range-t-il le nombre de places ?

Le compteur du Cyclone, le grand-huit de Coney Island, tient en quatre lignes. Suis la boîte places :

Ligne 1places = 24
La boîte places reçoit 24.
Ligne 2montes = 3
La boîte montes reçoit 3.
Ligne 3places = places - montes
24 − 3 = 21 : le 24 est perdu.
Ligne 4print(places)
Le panneau affiche 21.

🧠 À retenir : une variable est une boîte de la mémoire, avec une étiquette (son nom) et une seule valeur. Le signe = range une valeur et remplace l'ancienne.

⚠️ Le piège : lire = comme « est égal à ». Il veut dire « range » ; pour comparer, Python écrit ==.

2. Comment lire un programme sans ordinateur ?

Deuxième journée au Cyclone. Ta table de suivi a une colonne par boîte ; ton doigt suit chaque ligne :

Ligne 3places = places - montes
24 − 5 = 19, rangé dans places.
Ligne 5places = places + descendus
19 + 2 = 21 : la boîte repart de 19.
Le motif compteurtotal = total + 2, répété : la boîte accumule.

🧠 À retenir : tu lis avec une table de suivi. Chaque ligne calcule à droite, puis range à gauche.

⚠️ Le piège : repartir de 24 à la ligne 5. La boîte contient 19 : seule la valeur du moment compte.

3. Pourquoi le compteur affiche-t-il 87 places pour un train de 24 ?

Dans l'éditeur Vittascience, deux expériences, presque pareilles :

Des nombresprint(20 + 4) affiche 24 : les nombres s'additionnent.
Du texteprint("20" + "4") affiche 204 : les textes se collent.
Le compteur fou« 87 » : quelqu'un a mis des guillemets, et « 8 » s'est collé à « 7 ».

🧠 À retenir : entre guillemets, c'est du texte, même des chiffres. Le signe + additionne les nombres, mais colle les textes.

⚠️ Le piège : croire que ce sont les mêmes chiffres, donc la même chose. 4 se calcule, "4" s'affiche.

4. Comment savoir si le programme répond au besoin ?

Le besoin : afficher le bon nombre de places libres. Le banc de tests du responsable :

T1 ✔ Personne ne bougeAttendu 24, obtenu 24.
T2 ✔ 3 montentAttendu 21, obtenu 21.
T3 ✘ 2 descendentAttendu 23, obtenu 19.
Le diagnosticLa ligne 5 soustrait les descendus. T3 le prouve.

🧠 À retenir : tester, c'est comparer le résultat attendu et le résultat obtenu, sur plusieurs cas. Un seul test raté suffit : le programme ne répond pas au besoin.

⚠️ Le piège : s'arrêter après T1 et T2 en disant « ça marche ». Le bug attendait le premier visiteur qui descend.

5. Comment modifier le programme sans rien casser ?

Le responsable valide ton diagnostic, et le Cyclone reçoit un nouveau train de 32 places :

Corriger le bugLa ligne 5 devient
places = places + descendus.
Le nouveau trainSeule la ligne 1 change : places = 32. Le nombre de sièges n'est écrit qu'une fois.
Puis rejouerT1, T2 et T3, tous les trois, pas seulement celui qui échouait.

🧠 À retenir : modifier, c'est changer la bonne ligne. Ensuite, tu rejoues tous les tests : une correction peut casser ce qui marchait.

⚠️ Le piège : changer le nombre de sièges partout où tu le vois. Avec une variable, il n'est écrit qu'à un seul endroit.

6. Comment la variable commande-t-elle la barrière ?

La barrière du manège obéit à if places > 0: ouvrir, else: fermer. Son banc de tests :

B1 et B210 places, puis 32 : la barrière s'ouvre.
B3, la frontière0 place : « 0 > 0 » est faux, la barrière se ferme.
Avec >= ✘À zéro place, la barrière resterait ouverte.
L'ordre descendLa valeur de places devient un ordre, envoyé à la commande du moteur : l'information commande l'énergie.

🧠 À retenir : une condition fait choisir le programme entre deux actions. La barrière n'est réglée que si tous les tests passent, la frontière comprise.

⚠️ Le piège : écrire places >= 0 « pour être sûr ». À zéro place, le visiteur de trop entrerait.

📖 Les mots de la séquence

variable — variable
une boîte de la mémoire : un nom, une valeur.
valeur — value
ce que contient la boîte à un moment donné.
affecter — to assign
ranger une valeur avec le signe =.
instruction — statement
une ligne du programme, un ordre à exécuter.
table de suivi — trace table
le contenu des boîtes, ligne après ligne.
texte — string
des caractères entre guillemets : ils ne se calculent pas.
console — console
la zone où le programme affiche ses résultats.
tester — to test
comparer l'attendu et l'obtenu.
besoin — need
ce que le programme doit permettre de faire.
bug — bug
une erreur qui fait mal fonctionner le programme.
diagnostic — diagnosis
ce qui ne va pas, la ligne coupable, et le test qui le prouve.
condition — condition
une question dont la réponse est vraie ou fausse.
frontière — edge case
la valeur pile à la limite, comme 0 place.
non-régression — regression testing
rejouer tous les tests après une modification.
OST — technical object or system
un objet ou système technique : la barrière.
