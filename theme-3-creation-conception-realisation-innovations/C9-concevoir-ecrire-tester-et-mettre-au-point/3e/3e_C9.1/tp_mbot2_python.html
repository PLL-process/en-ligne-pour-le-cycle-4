🧰 Avant la séance 1 (échauffement) — les six gestes de mBlock

Pour que le vrai robot obéisse, il faut lui envoyer ton programme.
Ce sont toujours les six mêmes gestes, dans mBlock, le logiciel du robot.

  1. Ouvre mBlock.
    Dans l’onglet « Appareils », ajoute « CyberPi » : c’est le boîtier à écran posé sur le robot.
  2. Branche le robot à l’ordinateur avec son câble USB.
    Allume-le.
  3. Clique sur « Connecter ».
    Garde le port proposé, puis valide.
  4. Choisis le mode « Téléverser ».
    L’autre mode s’appelle « En direct » : ce n’est pas celui-là.
  5. Choisis « Python » à la place de « Blocs », en haut de la zone de programme.
    Efface ce qui s’y trouve.
    Écris ou colle ton programme.
  6. Clique sur « Téléverser ».
    Le programme part dans le robot, et démarre dès qu’il est arrivé.

D’une version de mBlock à l’autre, un bouton peut changer de nom ou de place.
Si tu ne le trouves pas, demande à ton professeur.

Le programme, dans l’ordre :

Ligne par ligne :

  1. import cyberpi
    → on apporte les commandes du robot.
  2. cyberpi.console.println("Y")
    → le robot écrit Y, puis passe à la ligne.
  3. cyberpi.console.print("X")

  4. cyberpi.console.println("Z")

💡 Aide 1 — un indice

La ligne décalée de 4 espaces est celle qui se répète pendant l’attente.
Elle se place juste sous la ligne qui finit par deux-points.

🧭 Aide 2 — la démarche

1. Les bibliothèques.
2. while not … : se lit « tant que la manette n’est pas poussée vers le haut ».
3. Dessous, décalée : la courte pause, répétée tant qu’on attend.
4. La ligne qui n’est pas décalée ne s’exécute qu’après l’attente.

📖 Correction complète (à ouvrir après ton essai)

Le programme, dans l’ordre :

    time.sleep(0.05)
cyberpi.mbot2.forward(speed=40, run_time=1)

Ligne par ligne :

  1. import cyberpi, time
    → les commandes du robot, et celles du temps.
  2. while not cyberpi.controller.is_press('up'):
    → tant que la manette n’est pas poussée vers le haut, on répète ce qui est décalé dessous.
  3.     time.sleep(0.05)
    → une pause de 5 centièmes de seconde, puis on regarde de nouveau la manette.
  4. cyberpi.mbot2.forward(speed=40, run_time=1)
    → la boucle est finie : le robot avance 1 seconde à 40 tours par minute, puis s’arrête.

A7 Le robot qui évite les obstacles

pas encore fait

Touche une étiquette : elle va dans le trou encadré de jaune (le premier trou vide). Ou fais-la glisser dans le trou de ton choix.

💡 Aide 1 — un indice

Commence par ce qui se lit dans les trois cas : le son de chaque cas, la distance d’alerte, la vitesse.
Une ligne qui finit par deux-points annonce un cas : elle n’est pas décalée comme les lignes qu’elle commande.

🧭 Aide 2 — la démarche

1. Trou 1 : un programme commence par ses bibliothèques.
2. Trous 2, 3 et 4 : trois nombres. Lis le commentaire de chaque ligne, puis les trois cas.
3. Trou 5 : la seule ligne qui range une mesure dans d.
4. Trou 7 : entre if et else, le deuxième cas s’écrit avec elif.
5. Trous 6 et 8 : un son par cas, écrit plus haut.
6. Trou 9 : après le recul, le robot tourne.
7. Trou 10 : la pause, alignée sous if, se fait à chaque tour.

📖 Correction complète (à ouvrir après ton essai)

Le programme complet :

import cyberpi, time
SEUIL = 15
PORT = 1
VITESSE = 50

while True:
    d = cyberpi.ultrasonic2.get(index=PORT)
    if d is None or d == 0:
        cyberpi.led.on(255,0,0,"all")
        cyberpi.mbot2.EM_stop(port="all")
        cyberpi.audio.play("buzzing")
    elif d < SEUIL:
        cyberpi.led.on(255,165,0,"all")
        cyberpi.mbot2.EM_stop(port="all")
        cyberpi.audio.play("laugh")
        cyberpi.mbot2.backward(speed=VITESSE, run_time=0.4)
        cyberpi.mbot2.turn(135, speed=VITESSE)
    else:
        cyberpi.led.on(0,255,0,"all")
        cyberpi.audio.play("hello")
        cyberpi.mbot2.forward(speed=VITESSE)
    time.sleep(0.1)

Trou par trou :

  1. import cyberpi, time
    → le robot et les pauses.
  2. 15
    → le cas 2 dit « à moins de 15 centimètres ».
  3. 1
    → le capteur de distance est le premier branché.
  4. 50
    → le cas 3 dit « 50 tours de roue par minute ».
  5. d = cyberpi.ultrasonic2.get(index=PORT)
    → on mesure, et on range la mesure dans d. Sans cette ligne, d n’existe pas.
  6. cyberpi.audio.play("buzzing")
    → pas de mesure : le bourdonnement.
  7. elif d < SEUIL:
    → « sinon, si la distance est plus petite que le seuil ».
  8. cyberpi.audio.play("laugh")
    → obstacle : le rire.
  9. cyberpi.mbot2.turn(135, speed=VITESSE)
    → le robot se détourne de 135 degrés vers la droite.
  10. time.sleep(0.1)
    → un dixième de seconde entre deux mesures.

L’erreur fréquente : échanger 15 et 50.
Le programme marche, mais ce n’est plus le robot demandé : il s’arrête à 50 centimètres de l’obstacle, et roule à 15 tours par minute.

Pourquoi des noms en majuscules ?
SEUIL, PORT et VITESSE sont des réglages.
Écrits une seule fois, en haut, ils se changent en un seul endroit.

🌈 Convertisseur de couleurs

Une couleur de lumière se règle avec trois nombres de 0 à 255 : rouge, vert, bleu.
Le même réglage peut s’écrire en un seul code, le code hexadécimal : le signe #, puis deux caractères par couleur.
Change une case : l’autre écriture et l’aperçu suivent.

Exemples : #FF0000 rouge · #00FF00 vert · #0000FF bleu

Aperçu :

À utiliser avec : cyberpi.led.on(rouge, vert, bleu, "all")

pas encore fait

💡 Aide 1 — un indice

Le code a trois paires de caractères : une pour le rouge, une pour le vert, une pour le bleu.
255 s’écrit FF, et 0 s’écrit 00.

🧭 Aide 2 — la démarche

1. Écris le signe #.
2. Remplace chaque nombre par sa paire : 255 → FF, 0 → 00.
3. Garde l’ordre rouge, vert, bleu.
Tu peux vérifier avec le convertisseur de couleurs.

📖 Correction complète (à ouvrir après ton essai)

Réponse : #FFFF00

Rouge 255 → FF.
Vert 255 → FF.
Bleu 0 → 00.

L’erreur fréquente : s’arrêter à #FFFF.
Même à zéro, le bleu s’écrit : 00.

E4 Écrire sur l’écran : print ou println ? (2 points)

pas encore fait

Quelle phrase est vraie ?
💡 Aide 1 — un indice

Repense à l’activité A1 : pourquoi le X et le Z étaient-ils sur la même ligne ?

🧭 Aide 2 — la démarche

1. Dans A1, print("X") est suivi de println("Z").
2. Le Z s’écrit juste après le X : print n’est donc pas passé à la ligne.

📖 Correction complète (à ouvrir après ton essai)

Chaque proposition, une par une :

  • « print et println font la même chose. »
    → ✘ l’une passe à la ligne, l’autre non.
  • « print efface tout l’écran avant d’écrire le nouveau texte. »
    → ✘ aucune des deux n’efface l’écran.
  • « println passe à la ligne après avoir écrit ; print, non. »
    → ✔ c’est ce qui plaçait le X et le Z côte à côte dans l’activité A1.

Le décalage (l’indentation).
Les lignes qui se répètent sont décalées de 4 espaces sous la ligne qui finit par deux-points.
La première ligne qui n’est plus décalée vient après la boucle.

for i in range(3):
    print("Bonjour !")   # décalée : répétée 3 fois
print("Fini")            # pas décalée : une seule fois, après la boucle

📖 Corrigé du Bonus (à ouvrir APRÈS ton essai)

1. La variable qui ment.

Exemple : on met la vitesse entre guillemets.

import cyberpi
cyberpi.mbot2.forward(speed="40", run_time=1)

Python s’arrête et affiche une erreur de type : TypeError.
Le message exact change selon l’appareil, mais ce mot y est presque toujours.

En français, pour quelqu’un qui ne programme pas :
« Tu me donnes un texte là où j’attends un nombre : je ne sais pas rouler à la vitesse d’un texte. »

Pourquoi : "40", entre guillemets, est un texte ; 40 est un nombre.
Ils se ressemblent à l’écran ; pour Python, ce sont deux types différents.

2. Le robot sans robot.

Exemple : la fonction n’envoie rien aux moteurs ; elle écrit ce qu’elle aurait commandé.

def avancer(vitesse, duree):
    print("AVANCER à", vitesse, "tours par minute pendant", duree, "s")

avancer(40, 1)

À quoi sert un programme qui ne pilote rien :
· à vérifier l’ordre des actions et les valeurs sans robot : à la maison, ou quand il n’y a qu’un robot pour quatre ;
· à trouver les erreurs avant de risquer le matériel ;
· à garder une trace écrite de ce que le robot fera.

C’est une simulation : elle prouve la logique, pas le mouvement réel (les roues peuvent patiner).
Le robot simulé de cette page fonctionne ainsi.

3. Le nom qui explique.

vitesse_tours_par_minute = 40
distance_securite_cm = 15    # 15 cm : la distance de sécurité devant un mur
duree_s = 0.5

Les commentaires devenus inutiles : ceux qui disaient seulement ce que contient la variable (« v est la vitesse », « t est la durée »).
Le nom le dit maintenant, avec son unité.

Celui qu’on garde : celui qui dit pourquoi (« 15 cm : la distance de sécurité devant un mur »).
