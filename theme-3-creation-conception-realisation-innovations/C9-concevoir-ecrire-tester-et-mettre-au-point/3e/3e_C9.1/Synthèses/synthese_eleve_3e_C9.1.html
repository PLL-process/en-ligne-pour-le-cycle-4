📄 Synthèse — Variables, types et systèmes

3e_C9.1 · Thème 3 · New York — ce qu'il faut savoir refaire

📦 La variable : une boîte étiquetée

  • Une variable = une étiquette (son nom) + UN contenu (sa valeur), dans la mémoire.
  • Le signe = ne dit pas « égal » : il dit « RANGE cette valeur dans la boîte » — et il remplace ce qui s'y trouvait (l'ancienne valeur est perdue).
  • minutes = minutes - 1 se lit de droite à gauche : je calcule d'abord (avec la valeur courante), je range ensuite.
  • total = total + x = le motif compteur (accumulation) — à reconnaître au premier coup d'œil.
  • Pour lire un programme sans se tromper : la table de suivi (une colonne par variable, une ligne par instruction).

🏷 Les types et leurs pièges

  • 3 + 4 → 7 (addition) mais "3" + "4" → "34" (collage = concaténation) : le TYPE décide du métier du +.
  • "21" - 1 → TypeError : on ne soustrait pas un nombre d'un texte. Les convertisseurs : int("21"), float("1.8"). En cas de doute : type(x).
  • = range · == compare — le if n'accepte que des questions.

🌬 Élaborer → traduire → mettre au point (le cœur de 3e_C9.1)

  • Élaborer : l'algorithme en français d'abord — les variables nécessaires, les conditions, dans l'ordre.
  • Traduire : une fonction par tâche — elle reçoit des variables, renvoie un résultat (return), s'appelle mille fois, se teste séparément.
  • Mettre au point : le banc de tests écrit À L'AVANCE — un test par cas du besoin + un test par FRONTIÈRE (à 100 pile, > ou >= ? c'est le cahier des charges qui tranche).
  • Après TOUTE correction : rejouer TOUS les tests (la non-régression). Un programme est fini quand il passe tous les tests — pas quand il « a marché une fois ».
  • Sur un système réel (🅰), la valeur renvoyée devient une commande : capteur → variable → fonction → actionneur — l'information pilote l'énergie.

🔎 La chasse aux bugs — les 3 familles du débutant

  • Le TEXTE déguisé en nombre (guillemets de trop) · la VIRGULE décimale (c'est un point) · l'OPÉRATION impossible entre types.
  • Méthode : table de suivi avec les types · lire le message d'erreur EN ENTIER · une correction à la fois, réexécuter à chaque fois · bug silencieux → print() aux étapes clés.

🎯 En une phrase

Une variable est une boîte étiquetée que le = remplit, dont le type décide des opérations possibles — et un programme n'est au point que lorsqu'il passe tous les tests, frontières comprises.
