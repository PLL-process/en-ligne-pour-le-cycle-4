↑ La carte

1. Qu'est-ce qu'une variable ?

Le panneau du quai exécute ces deux lignes. Regarde la boîte minutes :

1. minutes = 4La boîte reçoit 4.
2. minutes = minutes - 1Python calcule d'abord à droite : 4 − 1 = 3.
3. Puis il rangeLa boîte contient 3. Le 4 est perdu.

🧠 À retenir : une variable est une boîte avec une étiquette, son nom, et un seul contenu, sa valeur. Le signe = veut dire « range dans la boîte » : il remplace l'ancien contenu.

⚠️ Le piège : lire x = x + 1 comme une équation. C'est un ordre donné à la mémoire.

2. Comment suivre un programme sans l'exécuter ?

Le compteur du tourniquet, sans ordinateur : tu notes chaque variable après chaque ligne.

Ligne 1passages = 0
Ligne 2groupe = 3
Ligne 3passages = 0 + 3 = 3
Ligne 4groupe = 3 − 1 = 2
Ligne 5passages = 3 + 2 = 5

🧠 À retenir : la table de suivi note chaque variable après chaque ligne, avec sa valeur du moment. total = total + x est le motif du compteur.

⚠️ Le piège : répondre 6 à la ligne 5, avec l'ancien groupe. À cette ligne, groupe vaut déjà 2.

3. Pourquoi "3" + "4" donne-t-il "34" ?

Chaque valeur a un type, sa famille. Python en connaît quatre :

int : un entier4, 96
float : un décimal1.8, écrit avec un point.
str : un texte"Q", "34", entre guillemets.
bool : vrai ou fauxTrue ou False, le résultat d'une comparaison.

🧠 À retenir : le type décide de ce que fait l'opération. Entre deux nombres, le + additionne : 3 + 4 donne 7. Entre deux textes, il colle : "3" + "4" donne "34". En cas de doute, type(x) te le dit.

⚠️ Le piège : croire que "5" et 5 sont pareils. int("5") change le texte en nombre.

4. Comment trouver les bugs du panneau ?

Le stagiaire a laissé trois bugs dans le programme du panneau. Chacun appartient à une famille :

Le texte déguisé en nombre"2" + "1" donne "21", pas 3.
La virgule décimale1,8 : aucune erreur, un calcul faux.
L'opération impossible"21" - 1 : une erreur de type.

🧠 À retenir : tu tiens la table de suivi avec les types, et tu lis le message d'erreur en entier. Tu fais une correction à la fois, puis tu réexécutes. Avec 2 + 1 et 1.8, le panneau affiche Q - 96 St 2 min | 25.0 C.

⚠️ Le piège : s'arrêter quand « ça a l'air bon ». La virgule ne donne aucune erreur : seul un essai, ou un print() bien placé, la montre.

5. Comment passer du besoin au programme ?

La MTA, le métro de New York, veut ventiler la station selon l'air et les trains :

1. Élaborer, en françaisAir pollué, indice au-dessus de 100 : à fond (3). Sinon, un train arrive : moyen (2). Sinon : doux (1).
2. Traduire en fonctionvitesse_ventilation reçoit l'air et le train, et renvoie (return) une vitesse.
3. CommanderAu collège, la valeur renvoyée devient un ordre pour un vrai moteur.

🧠 À retenir : tu élabores l'algorithme en français avant de taper. Tu le traduis en fonctions : une par tâche, qui reçoit des valeurs et renvoie un résultat.

⚠️ Le piège : croire qu'une fonction sert à faire joli. Elle permet de rejouer le calcul avec d'autres valeurs, donc de le tester.

6. Quand un programme est-il au point ?

Le banc de tests s'écrit avant, d'après le besoin. La MTA précise : « à 100 exactement, ventiler à fond ».

T1 : air 150, pas de trainAttendu 3, obtenu 3.
T2 : air 60, un trainAttendu 2, obtenu 2.
T3 : air 40, pas de trainAttendu 1, obtenu 1.
T4 : air 100 pileAttendu 3, obtenu 1 : > devient >=.

🧠 À retenir : un banc de tests compte un test par cas du besoin, et un test par frontière. Après chaque correction, tu rejoues tous les tests : c'est la non-régression. Le programme est au point quand ils passent tous.

⚠️ Le piège : écrire air = 100 dans la condition. Un seul = range une valeur ; c'est == qui compare.

7. Quelles habitudes évitent les bugs ?

Quatre gestes de l'atelier et du QCM, à garder pour tous tes programmes :

Prédire, puis testerTu écris d'abord ce que la console va afficher. L'écart t'apprend quelque chose.
Un nom qui dit le contenutemperature_quai : sans espace, et on sait ce qu'il y a dedans.
Créer avant d'utiliserprint(message) avant message = … : erreur, la boîte n'existe pas encore.
Échanger deux boîtesIl faut une troisième boîte, temp, pour garder un contenu.

🧠 À retenir : tu prédis avant de tester : une prédiction ratée montre ce qu'il reste à comprendre. Une variable porte un nom clair, et elle existe avant qu'on s'en serve.

⚠️ Le piège : échanger a et b avec a = b, puis b = a. Après la première ligne, l'ancien contenu de a est perdu.

📖 Les mots de la séquence

variable — variable
une boîte avec un nom et une valeur.
affecter — to assign
ranger une valeur dans une variable, avec =.
table de suivi — trace table
chaque variable, après chaque ligne.
compteur — counter
une variable qui accumule.
type — data type
la famille d'une valeur.
int — integer
un nombre entier.
float — float
un nombre décimal, écrit avec un point.
str — string
un texte, entre guillemets.
bool — boolean
vrai (True) ou faux (False).
concaténation — concatenation
coller deux textes bout à bout.
erreur de type — type error
une opération entre deux types incompatibles.
bug — bug
une erreur dans un programme ; en français, bogue.
algorithme — algorithm
les étapes, dans l'ordre, écrites en français.
fonction — function
un sous-programme qui reçoit des valeurs et renvoie un résultat.
banc de tests — test suite
les tests écrits avant, frontières comprises.
non-régression — regression testing
rejouer tous les tests après une correction.
mise au point — debugging
corriger jusqu'à ce que tous les tests passent.
